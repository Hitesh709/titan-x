# TITAN X

Production-oriented FastAPI trading intelligence platform built with Python 3.13, SQLAlchemy 2 async, PostgreSQL, Redis, and Alembic.

## Quick start

1. Copy `.env.example` to `.env` and replace every `change-me` value with a strong secret.
2. Start dependencies and the API: `docker compose up --build`.
3. Migrations run automatically via the container entrypoint.
4. Call the protected readiness endpoint with `X-API-Key` set to `API_KEY`.

## Configuration

All runtime configuration is environment-based. Required production values:

| Variable | Description | Min length |
|----------|-------------|------------|
| `DATABASE_URL` | PostgreSQL connection string | — |
| `REDIS_URL` | Redis connection string | — |
| `API_KEY` | API authentication key | 32 chars |
| `JWT_SECRET_KEY` | JWT signing secret | 64 chars |
| `POSTGRES_PASSWORD` | Database password | 16 chars |
| `REDIS_PASSWORD` | Redis password | 16 chars |

Set `DOCS_ENABLED=false` in production unless authenticated API documentation is explicitly required.

## Migrations

Alembic is configured for async PostgreSQL with autogenerate support. All models are auto-discovered from `titan_x.models`.

| Action | Command |
|---|---|
| Apply all pending | `alembic upgrade head` |
| Create autogenerated revision | `alembic revision --autogenerate -m "description"` |
| Revert last migration | `alembic downgrade -1` |
| View history | `alembic history` |
| Show current revision | `alembic current` |
| Check pending migrations | `alembic check` |

### Workflow

1. Make changes to model classes in `src/titan_x/models/`.
2. Run `alembic revision --autogenerate -m "description"`.
3. Review the generated migration file in `alembic/versions/`.
4. Apply with `alembic upgrade head`.
5. Commit both the model change and the migration file.

## Endpoints

- `GET /api/v1/health/live` — liveness probe
- `GET /api/v1/health/ready` — readiness probe (checks PostgreSQL and Redis)
- `GET /api/v1/version` — application version and build info
- `GET /api/v1/monitoring/system` — full system health snapshot

All endpoints require the `X-API-Key` header with the value set in `API_KEY`.
